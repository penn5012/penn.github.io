# 第 2 月：AI 交互体验与多模态应用

## 本月定位

本月承接第 1 月已经完成的基础流式聊天应用，重点不是学习模型算法，而是发挥前端和移动端开发经验，把“能聊天的 Demo”升级成“用户愿意使用、异常时可恢复、后续能接入真实业务”的 AI 产品界面。

本月采用 **TypeScript 主线、Python 暂不展开**。模型调用可沿用第 1 月已有接口；涉及文件、图片、语音和长任务时，允许先用 Mock API 或本地假数据打通交互。API 密钥不得写入客户端，正式的服务端鉴权、数据库和模型代理将在第 3 月系统学习。

推荐节奏：每天 1.5—2.5 小时；每 7 天完成一个可运行里程碑。若某天工作繁忙，优先完成“动手任务”和“当日产出”，阅读材料可以挪到周末补齐。

## 前置条件

- 已掌握 TypeScript、React/Vue 或自己的移动端技术栈。
- 已完成基础聊天页面，能够发送消息并流式显示模型响应。
- 理解 system、user、assistant 三类消息和基本上下文概念。
- 会使用 Git 提交代码，会通过浏览器或移动端调试网络请求。
- 本地已具备 Node.js、包管理器和一个可运行的前端/移动端项目。

## 月度目标

1. 用显式状态机管理消息生命周期，避免布尔变量相互冲突。
2. 完成稳定的 SSE/流式渲染、停止生成、重试和重新生成。
3. 安全渲染 Markdown、代码块、引用和结构化结果卡片。
4. 支持文件上传、图片输入以及可选的语音入口。
5. 设计长任务进度、异常恢复、会话管理和本地持久化。
6. 完成键盘操作、屏幕阅读器提示、响应式布局和移动端体验优化。
7. 建立基础 UI 测试与核心交互测试，为下月迁移到 Node.js AI 后端做准备。

## 建议技术栈

- 语言：TypeScript
- Web：React + Vite（Vue、Next.js 也可，保持现有栈优先）
- 移动端：Flutter、React Native 或原生平台任选已有栈；至少完成移动端适配验证
- 状态管理：useReducer、XState 或项目已有状态库
- 流式协议：Fetch ReadableStream / SSE
- Markdown：react-markdown + remark-gfm，代码高亮可选 Shiki/Prism
- 数据校验：Zod
- 本地持久化：IndexedDB（可用 Dexie）或移动端安全存储
- 测试：Vitest + Testing Library；端到端测试可选 Playwright
- 样式与组件：沿用现有组件库，不为换技术栈消耗时间

## 最终项目

完成一个可运行的 **“多模态 AI 对话工作台”**，支持：

- 流式回复、停止生成、重试、重新生成与继续生成；
- Markdown、代码块复制、结构化卡片与工具状态展示；
- 文件上传、图片预览与发送，语音入口可选；
- 长任务步骤进度、失败重试和恢复提示；
- 多会话创建、重命名、搜索、删除和本地持久化；
- 空状态、加载状态、断网、超时、限流、内容过长等异常态；
- 桌面端与移动端适配，基础无障碍支持；
- 一个 Mock/适配层，使下月可以把数据源平滑替换为 Node.js 后端。

## 月末验收标准

- [ ] 消息状态至少区分 `queued`、`streaming`、`completed`、`cancelled`、`failed`。
- [ ] 快速连续发送、停止生成、网络失败时，界面无重复消息和错序。
- [ ] 流式内容渲染稳定，长回复不会导致明显卡顿或持续跳动。
- [ ] Markdown、代码块和外链经过安全处理，代码块支持一键复制。
- [ ] 结构化数据经过 Zod 校验，校验失败时回退为普通文本或错误提示。
- [ ] 文件上传有类型、大小、数量限制，并显示上传进度、失败原因与删除入口。
- [ ] 图片发送前可预览，发送后能与对应消息关联。
- [ ] 长任务可展示步骤、当前状态、耗时和失败节点。
- [ ] 会话刷新后仍可恢复，支持创建、重命名、搜索和删除确认。
- [ ] 断网、超时、429、服务错误都有明确且可操作的提示。
- [ ] 键盘可完成发送、停止、聚焦和复制等主要操作，关键状态有读屏提示。
- [ ] 至少覆盖消息 reducer、流式解析、重试/取消、结构化卡片四类测试。
- [ ] README 包含功能清单、运行方法、架构说明、已知限制和演示截图/视频。

## 第 1 天：确定产品范围与交互基线

**学习目标**：明确本月项目边界，把已有聊天 Demo 变成可持续迭代的产品项目。

**核心知识**：AI 对话与普通 IM 的差异；流式生成、工具执行、长任务带来的状态复杂度；“UI 状态”和“服务端事实”的区别。

**动手任务**：盘点第 1 月代码，画出发送消息到回复完成的时序；建立本月功能清单和“不做清单”；记录当前的 3 个体验问题和 3 个代码问题。

**当日产出/验收**：提交 `docs/month-02-scope.md` 或 README 小节，包含页面草图、关键流程、风险清单；现有项目能够正常启动。

**建议时间**：1.5 小时。

## 第 2 天：设计统一消息模型

**学习目标**：用类型系统表示文本、图片、文件、卡片和状态，而不是在组件里堆临时字段。

**核心知识**：联合类型、判别字段、不可变数据；`Message`、`ContentPart`、`Attachment`、`Usage` 等领域模型。

**动手任务**：定义消息与内容分段类型；给消息增加唯一 ID、角色、状态、时间、错误、附件和父消息 ID；编写 5 份示例数据。

**当日产出/验收**：TypeScript 无报错；文本、图片、文件和结构化卡片都能由统一消息模型表达；示例数据可在页面渲染。

**建议时间**：1.5—2 小时。

## 第 3 天：建立消息状态机

**学习目标**：解决 `isLoading`、`isError`、`isStreaming` 等布尔值组合失控的问题。

**核心知识**：有限状态机；允许的状态转换；事件驱动更新；消息级状态与会话级状态。

**动手任务**：用 `useReducer`、XState 或现有状态库实现 `queued → streaming → completed`，并支持 `cancelled`、`failed`；禁止非法转换。

**当日产出/验收**：用按钮或 Mock 脚本演示成功、取消和失败三条路径；状态标签与操作按钮始终匹配。

**建议时间**：2 小时。

## 第 4 天：封装流式数据解析层

**学习目标**：将网络流解析从 UI 组件中剥离。

**核心知识**：SSE 事件格式、`ReadableStream`、增量解码、半包/粘包、结束事件与错误事件。

**动手任务**：实现独立的 stream adapter；处理一个 JSON 事件被拆成多段、多个事件同时到达、结束标志缺失等情况；保留 Mock 流用于测试。

**当日产出/验收**：解析层可通过回调或异步迭代器稳定输出 token/event；至少用 3 组边界数据验证，无残缺字符。

**建议时间**：2—2.5 小时。

## 第 5 天：优化流式渲染性能

**学习目标**：避免每个 token 都触发整页重渲染。

**核心知识**：批量刷新、`requestAnimationFrame`、局部状态、列表 memo、自动滚动的用户意图判断。

**动手任务**：把 token 缓冲后按帧或固定间隔更新；仅在用户位于底部附近时自动滚动；用户向上查看历史时显示“回到最新”。

**当日产出/验收**：用长文本流验证页面不明显卡顿；向上滚动时不会被强制拉回底部；记录一次优化前后对比。

**建议时间**：2 小时。

## 第 6 天：实现停止生成与资源清理（周末整合）

**学习目标**：让用户能够真正中断请求，而不只是隐藏加载动画。

**核心知识**：`AbortController`、组件卸载清理、竞态条件、迟到响应、取消与失败的语义区别。

**动手任务**：接入停止按钮；切换会话或关闭页面时取消旧请求；使用 request ID 丢弃已失效的流事件；保留取消前已生成内容。

**当日产出/验收**：连续执行“发送—停止—切换会话—重新发送”10 次，无幽灵回复、错写会话或控制台异常。

**建议时间**：2—2.5 小时。

## 第 7 天：第一周集成与测试

**学习目标**：把消息模型、状态机和流式层组合成稳定基线。

**核心知识**：单元测试边界、可重复 Mock、回归测试清单。

**动手任务**：为 reducer 和 stream adapter 编写测试；修复重复发送、空消息、极快返回、取消后报错等问题；整理组件边界。

**当日产出/验收**：第一周里程碑标签；核心测试通过；README 有消息状态图和流式数据流说明。

**建议时间**：2—2.5 小时。

## 第 8 天：重试、重新生成与继续生成

**学习目标**：区分三种恢复操作，避免产生错误的上下文。

**核心知识**：原请求快照、幂等 UI、消息分支、重放上下文；“重试失败请求”和“重新生成回答”的差别。

**动手任务**：失败消息支持重试；已完成回答支持重新生成；截断回答支持继续生成；每次操作显示明确状态。

**当日产出/验收**：三类操作均可演示，旧消息不被错误覆盖；发送时使用的参数和上下文有可追踪快照。

**建议时间**：2 小时。

## 第 9 天：Markdown 安全渲染

**学习目标**：提供良好富文本体验，同时避免把模型输出当成可信 HTML。

**核心知识**：GFM、XSS、HTML 白名单、链接安全属性、增量 Markdown 的不完整语法。

**动手任务**：集成 Markdown 渲染；默认禁用原始 HTML；处理表格、列表、引用和链接；为流式未闭合语法提供可接受回退。

**当日产出/验收**：常见 Markdown 正确显示；恶意脚本不能执行；外链具有安全属性并有清晰样式。

**建议时间**：1.5—2 小时。

## 第 10 天：代码块体验

**学习目标**：把代码回答做成开发者可用的交互组件。

**核心知识**：语言标记、高亮加载成本、复制反馈、横向滚动与移动端布局。

**动手任务**：实现代码高亮、语言标签、复制按钮和复制成功反馈；长代码横向滚动；大代码块可折叠。

**当日产出/验收**：至少测试 TypeScript、JSON、Shell 和未知语言；桌面端与窄屏均不撑破布局。

**建议时间**：1.5—2 小时。

## 第 11 天：结构化输出与运行时校验

**学习目标**：把模型返回的数据安全转换为 UI，而不是直接假设字段永远正确。

**核心知识**：JSON Schema/结构化输出概念、Zod 运行时校验、宽容读取、降级策略。

**动手任务**：设计一种结果卡片 schema，例如商品推荐、行程或任务清单；实现文本/JSON 解码、Zod 校验和失败回退。

**当日产出/验收**：合法数据渲染卡片；缺字段、错类型、多余字段不会让页面崩溃，并能展示可理解的回退状态。

**建议时间**：2 小时。

## 第 12 天：结构化卡片与操作反馈

**学习目标**：将 AI 结果从“文字墙”升级为可操作界面。

**核心知识**：展示组件与领域数据解耦；主次操作；确认、成功、失败反馈；避免模型直接触发高风险操作。

**动手任务**：完成卡片布局、详情展开、复制/采纳/拒绝按钮；高风险按钮先进入确认态，只模拟操作结果。

**当日产出/验收**：键盘和触摸均可操作；同一卡片支持加载、成功、失败、禁用四种状态。

**建议时间**：2 小时。

## 第 13 天：工具调用过程可视化（周末整合）

**学习目标**：让用户理解 AI 当前是在思考、搜索还是等待外部系统。

**核心知识**：工具调用生命周期；过程信息与内部推理的边界；可折叠详情；确认式操作。

**动手任务**：用 Mock 事件展示 `requested → awaiting_confirmation → running → succeeded/failed`；实现搜索、查订单、创建任务三类工具卡片。

**当日产出/验收**：工具状态变化清晰；敏感操作未经确认不能进入运行态；不展示模型隐含推理内容。

**建议时间**：2—2.5 小时。

## 第 14 天：第二周集成与视觉回归

**学习目标**：统一文本、代码、卡片和工具过程的消息呈现。

**核心知识**：消息内容注册表/渲染器模式；组件隔离；视觉回归思路。

**动手任务**：重构统一 `MessageContentRenderer`；制作包含所有内容类型的测试会话；补齐错误边界和空值处理。

**当日产出/验收**：第二周里程碑可演示；新增内容类型无需修改消息外壳；保存桌面端和移动端基准截图。

**建议时间**：2—2.5 小时。

## 第 15 天：文件选择与上传模型

**学习目标**：设计可靠的文件输入流程。

**核心知识**：MIME 类型、扩展名不可信、文件大小/数量限制、上传状态、客户端预览与服务端校验边界。

**动手任务**：实现文件选择、拖拽（Web）或系统选择器（移动端）；校验类型、大小、数量；建立 `selected/uploading/uploaded/failed` 状态。

**当日产出/验收**：非法文件被阻止并说明原因；合法文件显示名称、大小、状态和移除入口；暂用 Mock 上传即可。

**建议时间**：2 小时。

## 第 16 天：上传进度、取消与重试

**学习目标**：让慢上传和失败上传可控、可恢复。

**核心知识**：上传进度事件、取消、重试、并发限制、文件级错误与整批错误。

**动手任务**：实现进度条、取消和单文件重试；限制同时上传数量；离开会话前提示仍有未完成上传。

**当日产出/验收**：模拟慢网和失败场景；取消后不再更新进度；单个文件失败不影响其他文件。

**建议时间**：2 小时。

## 第 17 天：图片输入与预览

**学习目标**：完成适合 Web/移动端的图片消息体验。

**核心知识**：图片尺寸、压缩、EXIF 方向、Object URL 清理、相册/相机权限提示。

**动手任务**：实现图片缩略图、全屏预览、删除和发送；可选做客户端压缩；移动端验证相册选择，相机入口可先保留接口。

**当日产出/验收**：图片方向正确，发送前后都可预览；删除或组件卸载后释放临时 URL；大图不会卡死界面。

**建议时间**：2 小时。

## 第 18 天：附件与消息上下文绑定

**学习目标**：确保附件不会被发到错误消息或错误会话。

**核心知识**：草稿态、消息提交事务、附件引用 ID、异步上传竞态、上传完成后发送策略。

**动手任务**：建立 composer draft；发送时冻结文字和附件快照；处理“上传中点击发送”“切换会话”“删除附件”等情况。

**当日产出/验收**：快速切换会话和并发上传测试无串单；失败附件有清晰处理选择；历史消息附件可重新查看。

**建议时间**：2 小时。

## 第 19 天：语音入口（可选增强）

**学习目标**：了解语音作为输入方式的交互闭环，不深入语音算法。

**核心知识**：录音权限、录制时长、音量/计时反馈、转写中状态、隐私提示、平台兼容性。

**动手任务**：实现录音按钮和权限流程，或用 Mock 音频完成“录制—试听—转写—编辑—发送”；不支持的平台显示替代方案。

**当日产出/验收**：拒绝权限、录制取消和转写失败均可恢复；转写结果发送前可编辑。若跳过语音，则补做图片压缩与测试。

**建议时间**：1.5—2 小时。

## 第 20 天：长任务进度模型（周末整合）

**学习目标**：为研究、分析、批处理等分钟级任务提供可理解的等待体验。

**核心知识**：确定进度与不确定进度；步骤状态；轮询、SSE 更新概念；耗时提示；后台继续的产品语义。

**动手任务**：定义任务和步骤类型；使用 Mock 事件实现排队、处理中、部分完成、成功、失败和取消；展示当前步骤与已耗时。

**当日产出/验收**：进度不是虚假的固定百分比；失败时指出具体步骤并提供重试；刷新前提示任务状态保存策略。

**建议时间**：2—2.5 小时。

## 第 21 天：第三周集成与多模态回归

**学习目标**：把文件、图片、可选语音和长任务串进同一对话链路。

**核心知识**：端到端场景测试、资源清理、弱网测试、权限失败测试。

**动手任务**：完成“上传图片和文档—发送—模型返回卡片—启动长任务—中途取消/重试”的演示场景；修复布局和状态问题。

**当日产出/验收**：第三周里程碑可一键演示；无 Object URL 泄漏和跨会话错写；记录一个 1—2 分钟演示视频。

**建议时间**：2—2.5 小时。

## 第 22 天：多会话数据模型

**学习目标**：从单页面消息列表升级为可管理的会话产品。

**核心知识**：会话 ID、标题、更新时间、置顶/归档、草稿、分页和当前会话状态。

**动手任务**：定义会话模型；实现创建、切换、自动标题 Mock、重命名；按更新时间排序。

**当日产出/验收**：至少可维护 20 个模拟会话；切换会话保留各自滚动位置和未发送草稿。

**建议时间**：2 小时。

## 第 23 天：本地持久化与数据迁移

**学习目标**：刷新页面后恢复会话，并为下月接入数据库保留清晰接口。

**核心知识**：IndexedDB/移动端存储、repository 模式、schema 版本、迁移、敏感信息不落盘原则。

**动手任务**：实现 `ConversationRepository` 接口和本地版本；保存会话、消息、草稿；加入简单 schema 版本迁移。

**当日产出/验收**：刷新或重启应用后数据恢复；损坏记录不会导致白屏；代码不依赖具体存储库实现。

**建议时间**：2—2.5 小时。

## 第 24 天：会话搜索、删除与空状态

**学习目标**：补全会话管理的真实使用细节。

**核心知识**：客户端搜索、删除确认、撤销、空状态文案、危险操作可恢复性。

**动手任务**：实现标题/内容搜索；删除前确认，删除后短时间可撤销；设计首次使用、无搜索结果、历史为空三种状态。

**当日产出/验收**：搜索结果可定位目标会话；删除当前会话后自动进入合理页面；误删可撤销。

**建议时间**：1.5—2 小时。

## 第 25 天：异常状态系统化

**学习目标**：把网络和模型错误转换为用户能采取行动的提示。

**核心知识**：离线、超时、401、403、413、429、5xx；可重试与不可重试错误；错误码与用户文案分层。

**动手任务**：建立统一错误类型和映射；实现行内错误、Toast、页面级错误边界；为超时、限流、文件过大提供针对性操作。

**当日产出/验收**：至少模拟 8 类错误；每种提示都回答“发生了什么、用户能做什么”；技术细节只进入调试日志。

**建议时间**：2 小时。

## 第 26 天：离线、恢复与重复提交防护

**学习目标**：在移动网络抖动和页面恢复时保持一致性。

**核心知识**：在线状态、请求队列边界、客户端幂等 key、应用前后台切换、恢复策略。

**动手任务**：离线时阻止或排队发送并明确提示；恢复联网后由用户确认重发；防止按钮连点产生重复消息；前后台切换后刷新任务状态。

**当日产出/验收**：断网—发送—恢复—重发路径可重复验证；消息不会重复；不承诺无法保证的“自动后台完成”。

**建议时间**：2 小时。

## 第 27 天：无障碍与键盘操作（周末整合）

**学习目标**：让核心对话流程可被键盘和辅助技术使用。

**核心知识**：语义化标签、焦点管理、ARIA live region、颜色对比、减少动态效果、触控目标尺寸。

**动手任务**：补全可见标签和焦点样式；流式状态用不过度打扰的方式播报；实现发送、换行、停止、聚焦输入框快捷键；支持 `prefers-reduced-motion`。

**当日产出/验收**：仅用键盘完成创建会话、发送、停止、复制和重试；读屏能识别主要按钮和状态；触控目标尺寸合理。

**建议时间**：2—2.5 小时。

## 第 28 天：移动端体验与响应式收尾

**学习目标**：发挥移动端背景优势，解决真实的小屏和软键盘问题。

**核心知识**：安全区、软键盘遮挡、动态视口、触摸滚动、底部输入栏、侧栏转抽屉、网络与电量考虑。

**动手任务**：完成手机宽度适配；处理输入法弹出、横竖屏、安全区；会话列表改为抽屉；长按/复制和图片预览适配触摸。

**当日产出/验收**：至少在一个真实移动设备或设备模拟器完整走通主流程；输入框不被键盘遮挡；无横向溢出。

**建议时间**：2—2.5 小时。

## 第 29 天：核心交互测试与质量门槛

**学习目标**：将关键体验固化为自动测试和人工回归清单。

**核心知识**：组件测试、用户行为测试、伪造计时器、Mock 流、不可测试代码的重构信号。

**动手任务**：补充状态机、流式解析、停止/重试、结构化卡片校验、附件状态测试；可选增加一条端到端主流程；运行类型检查和构建。

**当日产出/验收**：测试、类型检查和生产构建通过；核心路径不依赖真实模型 API；形成可重复执行的手工弱网/移动端清单。

**建议时间**：2—2.5 小时。

## 第 30 天：项目交付、演示与复盘

**学习目标**：把学习结果转化为作品集材料，并明确下月后端迁移接口。

**核心知识**：技术叙事、取舍说明、已知限制、前后端契约、可演示性。

**动手任务**：清理代码和调试输出；完成 README、架构图、状态图、功能截图；录制 3—5 分钟演示；列出下月所需 API 契约和服务端职责。

**当日产出/验收**：发布第 2 月版本标签；新人按 README 能运行；演示覆盖流式、停止、卡片、附件、长任务、异常恢复和移动端；所有月末验收项逐项打勾。

## 与第 3 月的衔接

第 3 月将进入 **Node.js AI 后端**。本月结束前，把所有数据访问抽象为以下接口或等价结构，避免后端接入时重写 UI：

- `ChatTransport`：发送消息、接收流事件、取消请求；
- `ConversationRepository`：会话和消息的增删改查；
- `UploadService`：文件上传、进度、取消和重试；
- `TaskService`：查询长任务状态、取消与重试；
- `AuthProvider`：先用 Mock 用户，后续替换为真实登录。

下月重点会把 Mock 和客户端直连模型替换为 Node.js/TypeScript 服务端，并补充 PostgreSQL 持久化、身份认证、密钥保护、限流、超时、重试和服务端流式转发。本月形成的交互契约、错误模型和测试用例将直接成为后端 API 的验收标准。
