# Learning task guidance

## Scope

Own `学习计划/`. The task may read all product code to create explanations, exercises and reviews grounded in the real repository.

## Boundaries

- Do not modify `frontend/`, `backend/`, root configuration or shared contracts unless the user explicitly requests a coding exercise to land in product code.
- Clearly separate facts observed in the repository from proposed future architecture.
- Keep the learning sequence aligned with the current project stage instead of introducing unrelated technologies.

## Learning workflow

1. Identify the actual code or contract being learned.
2. Explain the concept in plain language.
3. Create a small exercise with observable acceptance criteria.
4. Review the result against project conventions.
5. Record misconceptions, follow-up topics and the relevant commit or file paths.

Learning output should improve understanding without silently changing delivery scope.
