## 七、本月最终验收标准

### 功能验收

- [ ] 保留第 8 月确定性工作流主干，只将一个动态决策节点 Agent 化。
- [ ] Agent 能在知识库、订单和工单工具之间选择，并能在信息不足时追问。
- [ ] 简单请求直接执行，复杂请求最多生成 3～5 步可验证计划。
- [ ] 支持短期记忆和跨服务重启恢复，不同用户、租户、thread 不串数据。
- [ ] 长期记忆只保存授权信息，用户可查看和删除；业务实时状态始终从工具查询。
- [ ] 至少一个业务能力通过 MCP Server 暴露并由 MCP Client 调用。
- [ ] 创建/修改工单必须人工批准；批准、修改和拒绝路径均可用。
- [ ] UI 能显示进度、工具结果摘要、引用、审批卡片、停止和错误状态。

### 安全与可靠性验收

- [ ] 所有工具都有严格 Schema、超时、错误码和参数校验。
- [ ] 读取和写入权限分离；权限由后端可信身份判断，不由模型参数决定。
- [ ] 写操作有幂等键，重复审批或网络重试不会重复创建工单。
- [ ] Agent 有最大迭代、最大工具次数、总超时、预算和重复调用检测。
- [ ] MCP 连接有工具白名单、授权范围、响应大小限制和日志脱敏。
- [ ] Prompt Injection、越权查询和恶意工具返回不会绕过权限或审批。
- [ ] 依赖失败时能降级或安全退出，不出现无限循环。

### 评测与工程验收

- [ ] 固定测试集不少于 20 条，覆盖正常、边界、越权、故障和审批场景。
- [ ] 报告工具选择正确率、参数正确率、任务成功率、审批触发率、越权拦截率、平均迭代数、延迟和成本。
- [ ] 每次运行能通过 Trace ID 还原状态变化、工具调用、审批和终止原因。
- [ ] 至少完成一次单 Agent 与多 Agent 对照实验，主线架构选择有数据依据。
- [ ] 项目包含 README、架构图、权限矩阵、威胁模型、测试报告和 3 分钟演示。

## 八、本月复盘模板

月底用以下问题写一篇 800～1500 字复盘：

1. 哪个节点被 Agent 化？为什么它比固定分支更合适？
2. 哪些节点坚持使用确定性代码？它们承担了哪些安全责任？
3. 测试集中最常见的三类失败是什么？最终分别通过 Prompt、工具 Schema、上下文、权限还是退出条件解决？
4. 上下文裁剪前后，Token、延迟和成功率如何变化？
5. 哪些数据进入短期记忆，哪些进入长期记忆，哪些坚决不进入记忆？
6. 人工审批如何避免重复执行、越权和过期重放？
7. MCP 带来了什么标准化收益，又增加了哪些信任边界？
8. 多 Agent 实验是否优于单 Agent？如果没有，增加的复杂度体现在哪里？
9. 如果系统明天上线，最担心的三个风险和监控指标是什么？
10. 第 10 月使用 n8n 时，哪些是外围业务自动化，哪些核心权限和 Agent 能力仍必须留在后端？

## 九、衔接第 10 月：n8n 业务自动化

第 10 月不要把本月的 Agent 逻辑全部拖进 n8n。推荐边界如下：

- **保留在 TypeScript 后端/LangGraph**：身份与权限、Agent 状态、知识库检索、工具白名单、人工审批、幂等写入、Trace 和安全退出。
- **交给 n8n**：表单/邮件/Webhook 触发、定时任务、调用 Agent API、同步 CRM/表格、给负责人发送通知、汇总运营报表。
- **衔接接口**：准备 `/agent/runs`、`/agent/runs/:id`、`/approvals/:id` 等 API 或等价接口；响应包含运行状态、下一步动作、Trace ID 和幂等键。
- **下月第一个验证场景**：客户反馈进入 n8n → 分类与清洗 → 调用本月 Agent → 若需工单则等待审批 → 回写业务系统 → 通知负责人。

完成本月后，你应能在面试中清晰表达：**我不是把全部业务交给一个自由运行的 Agent，而是在确定性工作流中嵌入受限的单 Agent，用 MCP 标准化工具接入，并以权限、人工审批、退出条件、Trace 和评测保证它可控。**
- **今日重点**：把自治范围限制在可观测、可退出、可审批的边界内，并验证Agent化是否优于普通工作流。

4. **补充测试**：为核心逻辑添加自动化测试；无法自动化时写清人工步骤。
5. **联调体验**：检查加载、成功、失败、取消或重试等用户可见状态。
6. **保存证据**：保留命令输出、测试报告、截图、Trace或评测记录。
7. **小步提交**：提交信息只描述今天完成的能力，不写“update”或“fix stuff”。
