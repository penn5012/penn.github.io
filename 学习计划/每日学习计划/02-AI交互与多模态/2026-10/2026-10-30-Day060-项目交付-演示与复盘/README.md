## 月末复盘清单

### 产品与交互

- [ ] 用户是否随时知道系统处于等待、生成、执行工具还是失败状态？
- [ ] 每个失败状态是否提供明确的下一步，而不是只显示“出错了”？
- [ ] 停止、重试、重新生成和继续生成的语义是否清楚？
- [ ] AI 返回结构化结果时，是否仍经过校验和用户确认？
- [ ] 长任务是否如实表达进度，没有伪造精确百分比？

### 工程质量

- [ ] 网络解析、领域状态、持久化和视图组件是否解耦？
- [ ] 是否通过 request ID、AbortController 等机制处理竞态？
- [ ] 是否清理临时 URL、订阅、计时器和未完成请求？
- [ ] 是否保留 Mock adapter，使测试不依赖真实模型和网络？
- [ ] 是否有测试覆盖最容易出错的状态转换和恢复路径？

### Web 与移动端体验

- [ ] 长回答、长代码、多个附件在窄屏下是否仍可用？
- [ ] 软键盘、安全区、触控目标和横竖屏是否验证？
- [ ] 键盘用户和读屏用户能否完成核心流程？
- [ ] 弱网、断网和应用前后台切换是否有合理反馈？

### 作品集表达

- [ ] 能否用 2 分钟解释消息状态机和流式渲染设计？
- [ ] 能否说明为何结构化卡片必须做运行时校验？
- [ ] 能否展示一次真实的错误恢复和移动端交互？
- [ ] README 是否包含运行方式、架构、测试、限制和后续计划？

## 与第 3 月的衔接

第 3 月将进入 **Node.js AI 后端**。本月结束前，把所有数据访问抽象为以下接口或等价结构，避免后端接入时重写 UI：

- `ChatTransport`：发送消息、接收流事件、取消请求；
- `ConversationRepository`：会话和消息的增删改查；
- `UploadService`：文件上传、进度、取消和重试；
- `TaskService`：查询长任务状态、取消与重试；
- `AuthProvider`：先用 Mock 用户，后续替换为真实登录。

下月重点会把 Mock 和客户端直连模型替换为 Node.js/TypeScript 服务端，并补充 PostgreSQL 持久化、身份认证、密钥保护、限流、超时、重试和服务端流式转发。本月形成的交互契约、错误模型和测试用例将直接成为后端 API 的验收标准。
- **今日重点**：把概率性、长耗时的模型行为转成用户能理解、能取消、能恢复的产品交互。

### 推荐执行顺序

1. **建立基线**：先运行当前项目并保存改动前的结果。
2. **最小实现**：只实现今天最核心的一条成功路径。
3. **失败路径**：主动制造空输入、超时、错误数据或无权限中的至少一种情况。
4. **补充测试**：为核心逻辑添加自动化测试；无法自动化时写清人工步骤。
5. **联调体验**：检查加载、成功、失败、取消或重试等用户可见状态。
6. **保存证据**：保留命令输出、测试报告、截图、Trace或评测记录。
7. **小步提交**：提交信息只描述今天完成的能力，不写“update”或“fix stuff”。

1. 先把问题缩小为稳定可复现的最小样例。
2. 确认输入、配置、网络、依赖服务和数据状态是否与预期一致。
3. 先画清消息状态迁移，再检查UI分支。
4. 验证取消请求后网络层和界面状态是否同时停止。
5. 在弱网、空数据和错误响应下分别复测。
6. 修复后重新运行原失败样例和一条正常回归样例。
