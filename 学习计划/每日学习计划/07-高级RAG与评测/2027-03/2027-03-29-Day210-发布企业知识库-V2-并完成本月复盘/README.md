## 九、本月复盘模板

在第 30 天用以下问题完成 `monthly-retrospective.md`：

1. V1 最大的问题是漏召回、排序靠后、过滤错误，还是生成失真？证据是什么？
2. 混合检索分别改善了哪些题型，又伤害了哪些题型？
3. Query Rewrite、HyDE、Rerank 各自带来多少收益、延迟和成本？哪些应条件启用？
4. 哪类文档最需要专属 Chunk 策略？表格和复杂 PDF 还有哪些已知问题？
5. 多租户权限在哪一层强制执行？怎样证明越权内容没有进入模型上下文？
6. 100 条评测集是否覆盖真实业务？哪些线上反馈应该加入下一版？
7. 人工评审分歧来自评分标准、文档冲突，还是答案本身含糊？
8. V2 上线前的阻断项、可接受问题和后续优化项分别是什么？
9. 如果流量增长 10 倍，最先出现的延迟、成本或数据一致性问题是什么？
10. 本月哪项优化最值得保留，哪项“看起来先进但暂时不划算”？

## 十、与第 8 月 LangGraph 工作流的衔接

第 8 月将学习确定性工作流和 LangGraph。不要把本月所有检索步骤立刻做成自主 Agent；先把已经验证有效的组件暴露为边界清晰的函数/服务：

```text
authorizeRequest
  → classifyKnowledgeRequest
  → extractMetadataFilters / requestClarification
  → rewriteQuery（条件启用）
  → hybridRetrieve
  → rerank（条件启用）
  → checkEvidence
  → generateGroundedAnswer / abstain
  → collectFeedback
```

进入第 8 月前需要准备：

- 将每个步骤定义成明确输入、输出、错误类型和超时策略。
- 保留 requestId、tenantId、conversationId、filters、candidates、citations、needHuman 等状态字段。
- 标记需要条件分支的地方：信息不足、证据不足、权限拒绝、工具失败、需要人工确认。
- 将 100 条 RAG 评测继续作为工作流中“检索与回答节点”的回归测试。
- 明确哪些步骤必须确定性执行，哪些节点才允许 LLM 判断；权限、删除、外部写操作不得由模型绕过。

这样第 8 月学习 LangGraph 时，你构建的是一个有真实知识库、稳定评测和权限边界的业务工作流，而不是只有几个节点截图的流程 Demo。
- **今日重点**：通过固定数据集判断一次检索改动是否真的提高正确率，而不是只观察几个演示问题。
