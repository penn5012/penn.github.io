## 核心知识

- 一个可信的AI项目需要定义用户、痛点、流程、边界、指标和风险。
- “用了 RAG 和 Agent”不是需求；“缩短售后答复时间并减少无依据回答”才是目标。

### 概念自检

- [ ] 能用自己的话解释：- “用了 RAG 和 Agent”不是需求
- [ ] 能用自己的话解释：“缩短售后答复时间并减少无依据回答”才是目标

### 今日必须回答的问题

1. 用可验证的项目、评测和部署证据证明你能把AI需求做成产品，而不是包装成算法工程师。
2. 今天的改动解决了什么用户问题或工程风险？
3. 如果依赖服务失败，用户会看到什么，日志中能找到什么？
4. 怎样用最小测试证明今天的实现没有破坏已有功能？

## 动手任务

1. 编写背景、目标用户、核心痛点、用户故事和业务流程。
2. 定义功能范围与非目标，说明哪些动作需要人工审批。
3. 定义成功指标：检索命中、回答有据、工具成功、处理时长和用户反馈。
4. 记录关键约束：隐私、权限、成本、延迟和数据更新。

### 推荐执行顺序

1. **建立基线**：先运行当前项目并保存改动前的结果。
2. **最小实现**：只实现今天最核心的一条成功路径。
3. **失败路径**：主动制造空输入、超时、错误数据或无权限中的至少一种情况。
4. **补充测试**：为核心逻辑添加自动化测试；无法自动化时写清人工步骤。
5. **联调体验**：检查加载、成功、失败、取消或重试等用户可见状态。
6. **保存证据**：保留命令输出、测试报告、截图、Trace或评测记录。
7. **小步提交**：提交信息只描述今天完成的能力，不写“update”或“fix stuff”。
