AI应用与交互  - 能实现流式聊天、停止生成、重试、历史记录、结构化卡片和错误恢复。 - 能把工具执行状态、引用证据和人工审批清楚呈现给用户。 - Web或移动端在弱网、长内容和异常状态下仍可使用。  ### 3. 后端与数据  - 能使用 TypeScript 构建安全的 AI API，保护模型密钥。 - 能使用 PostgreSQL、pgvector、Redis 和 Docker Compose。 - 能实现鉴权、权限、限流、超时、重试、幂等、日志和配置管理。  ### 4. 知识库与RAG  - 能完成解析、清洗、切分、向量化、存储、混合检索、重排、引用和增量更新。 - 能实现元数据和用户权限过滤。 - 能使用至少100条代表性问题评测检索与生成，并分析失败原因。  ### 5. Agent工作流  - 能使用 LangGraph.js 表达状态、分支、循环、Checkpoint、暂停与恢复。 - 能实现结构化工具调用、参数验证、权限控制、人工审批和失败恢复。 - 能解释 ReAct、Planning、Memory、MCP 的用途与边界，不为了“像Agent”而增加不可控性。  ### 6. 生产化与安全  - 能部署服务并使用健康检查、日志、Trace、成本和延迟指标排障。 - 能处理 Prompt Injection、越权检索、工具注入、秘密泄漏和日志隐私风险。 - 能明确演示方案与真正生产环境之间仍存在的差距。  ### 7. 作品与表达  - 至少有两个清晰定位的项目案例，或一个覆盖RAG与Agent的主项目加一个独立前端/移动端AI体验项目。 - 每个主项目具有 README、架构图、需求文档、API文档、部署文档、测试/评测报告和演示视频。 - 能完成30秒自我介绍、3分钟项目介绍、10分钟深挖和一道AI应用系统设计。  ### 8. 求职闭环  - 有明确的岗位筛选规则，不投算法训练类岗位。 - 有基础简历、定制版本、投递追踪和面试复盘机制。 - 每次面试后能把反馈转换成文档、实验、项目或表达上的具体改进。  ## 未来90天后续路线  ### 第31—60天：扩大真实反馈  - 每周定制投递10—15个高匹配岗位，避免无差别海投。 - 每周完成一次模拟面试或真实面试复盘。 - 邀请5—10名真实用户试用项目，记录失败案例和体验反馈。 - 优先修复影响可信度的问题，不为追热点随意换框架。 - 尝试为一个开源AI应用项目修复文档、前端体验、TypeScript SDK或测试问题。  ### 第61—90天：强化一个岗位方向  根据市场反馈选择一条主线：  - **AI全栈方向**：强化鉴权、多租户、后台任务、部署、监控和端到端交付。 - **RAG方向**：强化复杂文档、混合检索、权限检索、评测和数据更新。 - **Agent方向**：强化状态持久化、工具安全、审批、恢复、Trace和工作流评测。 - **AI产品工程方向**：强化交互、需求验证、用户反馈、实验和指标闭环。  只选一条作为主线，其余保持能协作和能解释的水平。  ### 第91—120天：争取真实交付证据  - 完成一个真实客户、朋友团队、社区或开源项目中的小型AI需求。 - 把真实约束、迭代过程和结果写成新的项目案例。 - 根据实际面试数据调整简历和岗位范围。 - 如果回复率低，先检查岗位匹配和简历首屏；如果能进面但不过，优先修正项目深挖、系统设计和沟通表达。  ## 每周持续节奏建议  - 2小时：岗位筛选与定制投递。 - 2小时：非算法面试与系统设计练习。 - 2小时：项目维护和真实反馈修复。 - 1小时：文档、作品集和个人站点更新。 - 1小时：面试复盘与下一周调整。  最终目标不是把自己包装成算法工程师，而是让招聘者清楚看到：你能利用已有的前端/移动端优势，独立把一个 AI 需求做成可用、可控、可评测、可部署、可持续改进的产品。 |
