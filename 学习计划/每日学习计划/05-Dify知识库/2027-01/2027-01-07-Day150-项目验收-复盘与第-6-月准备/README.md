### 知识库与流程

## 九、与第 6 月 TypeScript 自建 RAG 的衔接

第 6 月不是推翻本月成果，而是把已验证的业务链路逐步替换为可控制的代码模块：

| 本月 Dify 能力 | 第 6 月 TypeScript 实现 | 需要保留的资产 |
|---|---|---|
| 文档导入与解析 | Node.js 文档处理管线 | 原始/清洗文档与数据清单 |
| 自动分段 | 可配置 Chunk 策略 | 分段实验与决策记录 |
| Embedding 与索引 | Embedding API + PostgreSQL/pgvector | 选型约束与元数据字典 |
| 知识检索节点 | TypeScript 检索服务 | 50 条评测问题与基线指标 |
| Chatflow 条件分支 | LangGraph.js 或普通状态工作流 | 流程图、节点输入输出契约 |
| Dify 应用 API | 自有 Fastify/NestJS API | 客户端交互和错误状态设计 |
| 引用与反馈 | 自有 citation/feedback 数据模型 | 引用 UI、反馈标签和真实样本 |

下月开始前应准备好：

- 最终清洗文档与元数据 CSV。
- 50 条以上固定评测问题及预期证据。
- Dify 基线结果、配置截图和已知缺陷。
- 一份清晰的数据流图与 API 输出结构。
- 第 6 月优先级：先实现最小检索链路，再做引用、过滤和评测，不一次性重写所有能力。

> 本月不安排算法题、模型训练或复杂数学。评价学习效果的标准，是能否根据业务需求搭建、调试、集成并评测一个可信的知识助手。
- **今日重点**：先用可视化平台跑通知识采集、清洗、切分、检索、生成和评测的完整链路。

### 推荐执行顺序

1. **建立基线**：先运行当前项目并保存改动前的结果。
2. **最小实现**：只实现今天最核心的一条成功路径。
3. **失败路径**：主动制造空输入、超时、错误数据或无权限中的至少一种情况。
4. **补充测试**：为核心逻辑添加自动化测试；无法自动化时写清人工步骤。
5. **联调体验**：检查加载、成功、失败、取消或重试等用户可见状态。
6. **保存证据**：保留命令输出、测试报告、截图、Trace或评测记录。
7. **小步提交**：提交信息只描述今天完成的能力，不写“update”或“fix stuff”。
