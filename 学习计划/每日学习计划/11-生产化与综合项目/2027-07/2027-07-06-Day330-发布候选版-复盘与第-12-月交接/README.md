## 月末复盘模板

在本月最后补充一份复盘，建议回答：

1. 哪三个生产故障在开发阶段最容易被忽略？本项目如何处理？
2. 哪些状态必须放 PostgreSQL，哪些可以放 Redis？为什么？
3. 如何从一个用户问题定位到具体 Prompt、检索配置、工作流和工具版本？
4. 哪些错误可以重试，哪些不能？如何避免重复创建工单？
5. Prompt Injection 防御中，哪些依赖模型，哪些必须由代码和权限系统保证？
6. 当前 RAG 和 Agent 回归集覆盖了什么，仍缺少哪些真实数据？
7. P95 与成本瓶颈在哪里？做过哪些优化，是否损害质量？
8. 如果明天出现故障，如何发现、定位、降级、恢复和复盘？
9. Web/移动端体验如何让不可预测的 AI 行为变得可理解、可取消和可恢复？
10. 面试时如何用“业务问题—架构选择—风险控制—指标结果”在 3 分钟内介绍项目？

## 与第 12 月的衔接

第 12 月不再大规模增加功能，而是把本月 Release Candidate 转化为求职作品集：

- 从本月文档中提炼一张清晰架构图和一页技术选型说明。
- 从回归、压测、成本与恢复报告中提炼可量化的项目成果。
- 把 Web/移动端演示剪成 3～5 分钟视频，突出引用、审批、断线恢复和可观测性。
- 准备“为什么用工作流而非全自主 Agent”“为什么选择 pgvector”“如何防止重复工具调用”等系统设计问答。
- 清理仓库结构、提交历史、环境变量示例和 README，确保面试官可以快速运行。
- 根据目标岗位描述调整项目表述，但不虚构线上规模、准确率或真实用户数据。

本月完成后，你交付的不再是一个“会聊天的 Demo”，而是一套能说明工程判断、质量控制、安全边界和生产意识的 AI 应用系统。这正是前端/移动端工程师转向 AI 应用工程师时最有价值的差异化证明。
- **今日重点**：让知识库与Agent系统具备部署、监控、回归、恢复和成本控制能力。

## 动手任务

打 `v1.0.0-rc` 标签或等价版本；从零部署并跑 Smoke Test；整理架构图、数据流图、部署与回滚、备份恢复、API、权限、安全、测试、评测、性能和成本报告；录制 Web 与移动端完整演示；复盘本月关键决策。

### 推荐执行顺序

1. **建立基线**：先运行当前项目并保存改动前的结果。
2. **最小实现**：只实现今天最核心的一条成功路径。
3. **失败路径**：主动制造空输入、超时、错误数据或无权限中的至少一种情况。
4. **补充测试**：为核心逻辑添加自动化测试；无法自动化时写清人工步骤。
5. **联调体验**：检查加载、成功、失败、取消或重试等用户可见状态。
6. **保存证据**：保留命令输出、测试报告、截图、Trace或评测记录。
7. **小步提交**：提交信息只描述今天完成的能力，不写“update”或“fix stuff”。

## 排错顺序

1. 先把问题缩小为稳定可复现的最小样例。
2. 确认输入、配置、网络、依赖服务和数据状态是否与预期一致。
3. 先查看健康检查、日志、Trace和Metrics，再修改代码。
4. 故障演练必须保留恢复步骤和结果。
5. 优化前后使用同一组请求比较P95、错误率和成本。
6. 修复后重新运行原失败样例和一条正常回归样例。
