## 本月复盘清单

### 概念理解

- [ ] 我能解释 Token、上下文窗口、温度、System Prompt、流式输出和幻觉。
- [ ] 我知道客户端显示的历史不等于每次都必须发送给模型的上下文。
- [ ] 我能说明 SSE、WebSocket 和普通 HTTP 在本项目中的取舍。
- [ ] 我知道结构化输出适合哪些场景，以及为什么仍需运行时校验。

### 工程能力

- [ ] 模型密钥没有进入客户端、日志或 Git。
- [ ] 我能独立完成 TypeScript 服务端模型调用和流式转发。
- [ ] 我实现了取消、超时、错误映射、重试入口和请求追踪。
- [ ] 我能处理多轮上下文、裁剪、重新生成和本地持久化。
- [ ] 自动化测试无需真实模型和网络即可运行。

### 产品与效果

- [ ] 聊天界面具备完整的空、加载、生成、完成、失败和取消状态。
- [ ] Markdown 与代码块安全、易读，在目标移动端或浏览器体验正常。
- [ ] 我记录了首 Token 时间、总耗时、Token 和估算成本。
- [ ] 我使用固定的 20 条问题比较过至少两个 Prompt 版本。
- [ ] 我能指出当前方案至少 3 个限制，而不是只展示成功案例。

### 作品集

- [ ] 项目有清晰 README、架构图、测试记录和演示视频。
- [ ] 新环境可以按文档独立启动。
- [ ] Git 提交历史能体现按功能递进的开发过程。
- [ ] 我可以用“问题—方案—难点—指标—取舍—结果”讲解项目。

## 下月衔接

第 2 月将以本月的 **AI Chat Lab** 为基础，重点升级 AI 原生交互体验，而不是重新建项目。建议保留下列扩展点：

1. 消息内容采用可扩展的 `parts` 结构，为文本、图片、文件、音频和工具卡片预留类型。
2. 上传流程与聊天发送流程解耦，支持上传进度、取消和失败重试。
3. 保留统一的结构化结果渲染层，便于加入图片理解结果、文件摘要和交互卡片。
4. 保留请求状态机与可取消机制，下一月会扩展到长任务、后台任务和多模态处理。
5. 整理本月最常见的 10 个 UX 问题，作为第 2 月优化的基准清单。

下月预期方向：文件与图片输入、结构化卡片、语音或相机入口、长任务进度、更完整的移动端交互，以及为第 3 月服务端持久化和权限系统做好接口准备。
- **今日重点**：一次模型请求如何从客户端经过自有服务端到达模型，并以安全、可中断的方式返回用户。

### 推荐执行顺序

1. **建立基线**：先运行当前项目并保存改动前的结果。
2. **最小实现**：只实现今天最核心的一条成功路径。
3. **失败路径**：主动制造空输入、超时、错误数据或无权限中的至少一种情况。
4. **补充测试**：为核心逻辑添加自动化测试；无法自动化时写清人工步骤。
5. **联调体验**：检查加载、成功、失败、取消或重试等用户可见状态。
6. **保存证据**：保留命令输出、测试报告、截图、Trace或评测记录。
7. **小步提交**：提交信息只描述今天完成的能力，不写“update”或“fix stuff”。

## 排错顺序

1. 先把问题缩小为稳定可复现的最小样例。
2. 确认输入、配置、网络、依赖服务和数据状态是否与预期一致。
3. 检查API Key是否只存在服务端。
4. 记录请求ID、状态码、首Token时间和完整耗时。
5. 用最小Prompt复现问题，再逐项恢复参数。
6. 修复后重新运行原失败样例和一条正常回归样例。
